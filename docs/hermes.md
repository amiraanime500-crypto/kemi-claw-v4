# تثبيت Hermes Agent بجانب Kemi-Claw

هذا تثبيت مستقل لوكيل [Hermes Agent الرسمي من Nous Research](https://github.com/NousResearch/hermes-agent)، وليس تغييرًا لاسم Kemi-Claw أو استبدالًا له.

## التثبيت

المتطلبات: Linux أو macOS، وGit، وPython بإصدار 3.11 أو 3.12 أو 3.13 مع وحدتَي `venv` و`pip`، واتصال بالإنترنت لتنزيل المصدر وحزم Python. يُفضّل استخدام إصدار حديث من Python ومكتبة SQLite المرفقة به.

من جذر مستودع Kemi-Claw:

```bash
bash scripts/install_hermes.sh
export PATH="$HOME/.local/bin:$PATH"
```

يثبّت السكربت الإصدار `v2026.8.31`، الذي يعرض رقم الحزمة `0.21.0`، ويتحقق من تطابق المصدر مع الالتزام:

```text
29112bef099274229cadff79cdff7bf7b99c4b77
```

ينزّل المصدر الرسمي إلى مجلد مستقل، وينشئ بيئة Python افتراضية، ثم يثبّت مجموعة اعتماديات Python المسماة `[all]` في ذلك الإصدار. لا يستخدم `sudo`، ولا يعدّل Python النظام أو اعتماديات Kemi، ولا ينسخ الشيفرة الخارجية إلى Git الخاص بهذا المشروع.

| المكوّن | المسار الافتراضي |
|---|---|
| مصدر Hermes | `~/.local/share/hermes-agent/` |
| بيئته الافتراضية | `~/.local/share/hermes-agent/venv/` |
| أمر التشغيل | `~/.local/bin/hermes` |
| الإعدادات | `~/.hermes/config.yaml` |
| ملف متغيرات البيئة والمفاتيح | `~/.hermes/.env` |
| الجلسات والمهارات والذاكرة | داخل `~/.hermes/` |

هذه المجلدات مستقلة عن المستودع. في بيئات العمل المؤقتة قد يلزم إعادة تنفيذ سكربت التثبيت بعد استعادة البيئة؛ ملفات الحزم والبيئات الافتراضية ليست جزءًا من المشروع المحفوظ في Git.

## ربط مزوّد النموذج

شغّل معالج الإعداد من طرفية تفاعلية:

```bash
hermes setup
hermes
```

اختر المزوّد والنموذج، ثم أدخل المفتاح أو أكمل تسجيل الدخول عبر الطريقة التي يعرضها Hermes. **لا ترسل المفاتيح في المحادثة ولا تضعها في المستودع.** يُنشئ المثبّت ملف `.env` بصلاحيات `600` للمالك فقط، لكنه لا يضيف بيانات مصادقة.

التثبيت والتحقق من الأوامر لا يعنيان أن محادثة النموذج تعمل بالفعل؛ يلزم إعداد المزوّد أولًا. لا يُشغّل السكربت الوكيل على أي هدف، ولا يبدأ خدمة أو بوابة رسائل، ولا يربط أدوات Kemi عبر MCP تلقائيًا.

## التحقق

```bash
hermes --version
hermes --help
hermes doctor
"$HOME/.local/share/hermes-agent/venv/bin/python" -m pip check
```

من الطبيعي أن يشير `doctor` إلى غياب تسجيل الدخول أو إضافات لم تُفعّل. أدوات المتصفح تحتاج تثبيتًا منفصلًا؛ لا ينزّل هذا السكربت Chromium أو تطبيق سطح المكتب أو حزم منصّات الرسائل.

قد يُحذّر `doctor` من مكتبة SQLite قديمة مرفقة بـPython النظام. يحتوي إصدار Hermes المثبّت على آلية توافق تختار وضع `DELETE` بدل `WAL` لقواعد بياناته الجديدة على الإصدارات المتأثرة بمشكلة WAL-reset. يُنصح رغم ذلك باختيار Python حديث عند إنشاء بيئة جديدة؛ السكربت لا يرقّي مكتبات النظام ولا يُخفي التحذير.

إذا كانت لديك إعدادات قديمة، راجع التغييرات قبل ترحيلها باستخدام:

```bash
hermes config migrate
```

يهيّئ السكربت مخطط إعدادات الملفات الجديدة فقط؛ لا يرحّل إعدادات مستخدم موجودة تلقائيًا.

## إعادة التثبيت وتخصيص المسارات

يمكن إعادة تنفيذ السكربت لإصلاح اعتماديات الإصدار نفسه دون حذف إعدادات Hermes أو جلساته. يرفض الكتابة فوق مجلد غير تابع للمصدر الرسمي، أو مصدر معدّل، أو إصدار مختلف، أو بيئة افتراضية غير صالحة. إذا حدّثت Hermes لاحقًا إلى إصدار آخر فلن يعيده السكربت إلى الإصدار المثبّت هنا.

يعرض هذا الأمر الخيارات:

```bash
bash scripts/install_hermes.sh --help
```

يمكن تحديد Python آخر عند **إنشاء بيئة جديدة**:

```bash
HERMES_PYTHON=/absolute/path/to/python3.13 bash scripts/install_hermes.sh
```

تُعاد الاستفادة من البيئة الموجودة؛ تغيير `HERMES_PYTHON` لا يستبدلها تلقائيًا. يدعم السكربت كذلك `HERMES_INSTALL_DIR` لتغيير مجلد المصدر و`HERMES_HOME` لتغيير مجلد البيانات. عند استخدام مجلد بيانات مخصّص، صدّر `HERMES_HOME` أيضًا في الطرفية التي تشغّل منها Hermes.

إذا لم تتعرف الطرفية على الأمر، استخدم المسار الكامل:

```bash
"$HOME/.local/bin/hermes" setup
```
